# AGENTS.md

Instructions for coding agents working on Chomp Chomp Panic!, a top-down 2D pixel-art kaiju game made in Unity. The player eats prey to grow, smashes buildings and survives a timed session. See [README.md](README.md) for the player-facing overview.

## Environment

- Unity **6000.5.6f1**, Universal Render Pipeline (2D), new Input System (`UnityEngine.InputSystem`). Don't use the legacy `Input` class.
- C# scripts live in `Assets/Scripts` (runtime) and `Assets/Editor` (editor-only), all in namespace `ChompChompPanic` (`ChompChompPanic.Editor` for editor code).
- Art is generated by Python 3 scripts in `ArtSource/` (Pillow; numpy for People and the kaiju). The hand-drawn kaiju (Mecha, Octo, Moth) share helpers in `ArtSource/kaiju_kit.py`.
- Git LFS stores images, audio, fonts, models and video (see `.gitattributes`). Make sure new binary assets match an LFS pattern.
- A Unity MCP server may be available for reading the console, inspecting scenes and running editor commands. Use it to check for compile errors after changing C#.

## Scenes and flow

- `Assets/Scenes/Title.unity` is build index 0. `TitleScreen.cs` draws the logo and menu. Menu entries come from `TitleScreen.BuildMenu`; the in-game pause menu (Esc) comes from `GameManager.ShowPauseMenu`. Both use `Menu.cs`.
- `Assets/Scenes/SampleScene.unity` is the game. `GameManager.cs` runs the whole session. It builds the player, prey, city, camera and HUD in code at `Start`, so the scene itself holds very little besides the `GameManager` and its serialized settings.
- The HUD and game-over screen use `OnGUI`.

## Game design rules to keep intact

- **Prey ladder.** Prey is data-driven via `GameManager.DefaultPreyTypes()`. Tiers roughly double in radius: people/soldiers 0.45 → cars/jeeps 0.9 → tanks 1.8 → jets 2.7. Something can eat another when its radius is at least `eatRatio` (1.05) times bigger.
- Add new prey by adding a `PreyType` entry, not by writing a new class, unless it needs a new `Movement` mode.
- Cars drive on the **left** (Japan), on roads only.
- The kaiju can only smash buildings no bigger than itself. Bigger ones block movement.
- Rivals must stay slightly slower than the player (`SpeedFactor` < 1) so the player can always escape or catch them.
- Playable kaiju live in the Kaiju Roster asset. Kaiju with `StartsUnlocked` off unlock one per win, in roster order. Any kaiju the player isn't playing can show up as a rival (`OtherKaijuChance`), locked or not. Kaiju select only appears once more than one kaiju is unlocked.
- The default session is 10 minutes.

## Art pipeline

1. Art is drawn procedurally, pixel by pixel, by `ArtSource/<Group>/build_*.py`. The scripts are deterministic and write into `Assets/Art/<Group>/`.
2. Sprite strips are listed with their frame size in `Assets/Art/<Group>/sprite_frames.json`. The city uses `city_atlas.json`, read at runtime by `CityMap`.
3. **Chomp Chomp Panic > Import Art** slices the strips (point filter, uncompressed, 64 px per unit) and assigns sprites by file name: `<prefix>[_<variant>]_<clip>.png`. Clips are idle, run/walk/side/fly, up, down, shoot, chomp, death.
4. Never hand-edit files in `Assets/Art/` that a script generates. Change the script and re-run it.
5. Keep the shared palette: navy outline `#10152D`, a dark, desaturated night city, a teal kaiju and warm-colored people.
6. Don't commit image-generation prompt files.

## Sound pipeline

1. Sound effects are synthesized by `ArtSource/Audio/build_sfx.py` (standard library only, deterministic) into `Assets/Audio/sfx_<name>.wav`.
2. **Chomp Chomp Panic > Import Audio** assigns `sfx_<name>.wav` to the `<name>Sound` field (`menu_move` -> `menuMoveSound`) in every build scene. Numbered variants, `sfx_<name>_<n>.wav`, fill a `<name>Sounds` array; use them for sounds that repeat a lot. To add a sound, add it to `SOUNDS` in the script and add a matching `AudioClip` field.
3. Music lives in `Assets/Audio/Music/music_<map>_<n>.wav`. It isn't generated, so it can be replaced freely. Import Audio streams it as stereo Vorbis and fills the `<map>Music` array (`music_tokyo_2` -> `tokyoMusic[1]`). `GameManager` hands the array to `MusicPlayer.Play`.
4. Play sounds through `SoundPlayer.Play`; it ignores null clips, so the game stays silent rather than broken without them. Never hand-edit the generated WAVs.

## Conventions

- Match the existing style: XML `<summary>` docs on public types and non-obvious members, `[Tooltip]` on serialized fields, and `[Header]` groups in the `GameManager` inspector.
- Make every new feature degrade gracefully when its art is missing. Existing code falls back to a grid, a tint or nothing.
- Always commit Unity `.meta` files with their assets. Don't commit `Library/`, `Temp/`, `Logs/`, `UserSettings/` or generated `.csproj`/`.slnx` files.
- Commit messages: short imperative subject in sentence case (e.g. "Add title screen with logo and Start Game / Quit menu"). For bigger changes, add a body explaining the what and why. Don't add AI co-author trailers.

## Releases

- Versions follow semantic versioning in **Player Settings > Version** (`bundleVersion` in `ProjectSettings/ProjectSettings.asset`). Builds read it as `Application.version`.
- Set it through the Unity editor (`PlayerSettings.bundleVersion`, via the Unity MCP), then save project settings. Only edit `ProjectSettings.asset` by hand when Unity is closed, or the editor may overwrite it.
- Before tagging, make sure Unity compiles cleanly.

## Verifying changes

There are no automated tests yet. After changing code:

1. Make sure Unity compiles cleanly (check the console, via the Unity MCP if available).
2. Play from `Title.unity` and exercise the change: move, eat, smash, get shot, game over, restart and return to title.
3. If you changed art, re-run the script, run **Import Art**, and check the preview PNG in `ArtSource/`.
